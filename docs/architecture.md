# Architecture

`aujitter run` owns collection, SQLite writes and the local Axum HTTP API. A database lock prevents multiple writers. `aujitter start` detaches that monitor, and the native GPUI application starts the same companion executable. The app session retains one worker and the native tray, independently of its presentation window. Closing the window releases its view/subscriptions; it leaves the tray and companion running. Explicit tray quit and Ctrl/Cmd+Q ask the service to stop gracefully before removing the tray. Native operations cross a bounded command channel; network requests and exports run on a worker thread. The backend uses two Tokio worker threads and a fixed number of concurrent probes.

Tray/menu objects stay on GPUI's main thread. Native callbacks enqueue intent through a bounded async channel; worker events refresh the shared session and notify subscribed windows without a polling/render loop. Backend status refreshes remain paced at five seconds. The tray never sends measurement probes. Unavailable or stale observations are labelled rather than displaying cached health as current. A stopped monitor can be started explicitly from the tray without changing saved preferences.

A per-user file lock prevents duplicate desktop/tray instances. A second foreground launch writes a local show-window request; the existing worker consumes it within about a second when idle. Background launches do not request a window. This mailbox opens only the app window, accepts no destructive commands, and adds no listening network port. Native integration uses [tray-icon](https://github.com/tauri-apps/tray-icon); the Linux KSNI backend avoids adding a GTK event loop to GPUI and requires a desktop StatusNotifierItem host. If tray construction fails, the window remains the available entry point.

Core modules separate validated settings, OS topology, bounded ICMP/TCP/DNS probes, rolling analysis, incident tracking, optional read-only UPnP and storage. SQLite WAL transactions record a sample, hourly aggregate and incident together. Raw sample expiry preserves longer-lived incidents. The CLI full export streams under the database lock; the GUI/web snapshot has an explicit scope. A slow or unavailable database causes the monitor to stop rather than silently lose evidence.

Topology is refreshed every 30 seconds, and gateway/DNS overrides invalidate it immediately. Router metadata is bound to the gateway that supplied it. Optional discovery runs at most every 30 minutes and WAN reads at most every minute outside gaming mode. Router responses are restricted to a numeric gateway IP, redirects/proxies are disabled, response sizes and request times are bounded, and only read actions are permitted.

The shared preset resolver chooses the effective Automatic profile from adapter/WAN evidence after topology refresh and router reads. It preserves manual gaming/pause controls and all network/privacy preferences. Runtime choices do not write configuration files; new samples record the applied profile and thresholds. Observation gaps consider the preceding cycle's interval so switching from slower to faster monitoring does not manufacture an outage. A WAN-type change resets the rolling comparison baseline.

The dashboard keeps up to 120 recent samples, 100 incidents and 24 hourly summaries. Analysis uses up to 120 samples and five minutes of comparable route data. Route changes reset the echo baseline. No catch-up bursts occur after sleep or slow probes. Observation gaps reset analysis before classification and do not extend an incident over unseen time. Defaults preserve detailed samples for 30 days and incidents/hourly summaries for a year; pruning runs hourly.

The HTTP API serves `/api/health`, `/api/dashboard`, `/api/settings`, `/api/control`, `/api/export`, and `/api/shutdown`. Settings writes are serialized and validated before replacement. The loopback listener checks Host to resist DNS rebinding. Origin and Fetch-Site checks reject cross-site browser requests; no permissive CORS is provided. Non-loopback listeners require a token. The page is served with a strict Content Security Policy, no-store headers and no inline scripts. Sensitive control and data endpoints check Bearer tokens when configured. Health exposes only app identity/version.

Future model-specific integrations should implement only documented read operations, use explicit user opt-in, bound traffic, and report freshness and provenance of signal/WAN data. No integrations should infer cellular 5G from Wi-Fi band names. Automated reboot, speed tests, credentials, ISP account access and packet capture are outside the current design.
